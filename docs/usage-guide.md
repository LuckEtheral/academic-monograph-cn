# 中文研究型专著 Skill 使用指南

版本：0.4.0（本项目默认可用发布版本）。Skill 名称：`chinese-research-monograph`；仓库名称：`academic-monograph-cn`。二者用于不同位置：调用时使用 skill 名称。

## 固定版本安装

从仓库取得本版时同时指定ref=v0.4.0和path=skills/chinese-research-monograph；可将该tag的完整技能目录放入隔离项目的.agents/skills/chinese-research-monograph/，显式调用后确认metadata.version为0.4.0，不自动替换已有项目或全局副本。

安装与文件校验见[固定版本说明](https://github.com/LuckEtheral/academic-monograph-cn/blob/v0.4.0/docs/install-v0.4.0.md)，阶段结果见[0.4.0公开摘要](https://github.com/LuckEtheral/academic-monograph-cn/blob/v0.4.0/evals/v0.4/RESULTS.md)。稳定版是本项目选择的默认可用版本，不是学术正确性认证。

## 先确定这次要做什么

本 skill 主要服务中文管理科学与工程研究型专著，重点为博弈分析、契约设计、信息不对称和决策优化。支持全书规划、章节写作、局部修订、跨章统稿，以及快速诊断、全书审阅、专项核查和修订复审；相近领域按实际问题和体裁使用。

写作与审核以中文学术专著规范为准，结合目标出版社的具体要求。英文文献可作为研究来源，英文专著可提供组织与讲解方法的参考；采用其章节形式前仍需核对中文专著规范。

安装完成且当前环境能够调用该 skill 后，可以在任务中写“使用 $chinese-research-monograph”，并说明任务和材料。提供文件可以采用当前对话附件，也可以提供当前环境能够读取的本地文件路径。路径不可访问时，需要改用可读取的文件或正文，不必重复上传已经可读的材料。

## 是否必须上传文献？按任务决定

|任务|开始工作所需材料|文献或其他补充材料|可以交付什么|
|---|---|---|---|
|规划全书|主题、目标读者、拟解决的问题；已有目录可一并提供|已有研究成果清单、摘要、目标出版社要求；暂无文献时也可先讨论架构|目录候选、章节分工、研究主线和具体待补材料；目录不等于已完成研究|
|依据研究写整章|本章问题和范围，核心来源的可读正文或作者自己的完整研究材料，需保留的结果与条件|理解关键模型所需的附录、证明、图表；全书目录或相关前章；有时需要数据和脚本|以已读来源和已有成果为依据的连续中文正文；缺失结论不凭空补出|
|润色或重构已有文字|需要处理的正文，以及允许调整和必须保留的内容|上下文、术语表、风格或出版社要求；涉及事实和模型核验时再补原件|该范围的修订文本与必要说明。仅有正文时，不默认同时完成来源核验|
|快速诊断或结构审阅|待审书稿、目录及审阅范围；全书系统审阅需要全部约定章节和图表附录|目标读者、出版社要求、作者最关心的问题|结构、表达、内部一致性等实际可查范围的报告；外部来源支持另列核读情况|
|核查引文或文献转述|待核段落、对应书目和相关原文；只有DOI、题名或链接时可先查找|必要附录、补充材料，以及实际采用版本|来源身份、内容支持和转述准确性判断；取不到正文时说明具体待核论断|
|复核数学或数值结果|实际公式、假设、证明或推导；数值任务另提供实际参数和数据|复现原计算时通常还需要脚本、运行说明和相关输入；解析复核不必先有代码|实际完成的推导检查、复算或运行记录，分别说明覆盖|
|跨章统稿或修订复审|各章准确底本及版本；复审需提供指定意见、修订稿和必要关联内容|术语/符号表、参考文献库、原版与修改说明、目标交付要求|授权范围的统稿候选或复审报告；保留模型差异与原件|

文献没有统一数量门槛。只上传和本次任务直接有关的资料；如果仅处理一个小节，无需先提交整本书和全部参考文献。计划、研究清单或摘要足以启动架构工作，但不能替代核心模型的原文。

核查合同筛选时，提供本次使用的合同菜单、真实类型与收益、选择后的可行动作和可行范围；核查约束化简时，提供完整目标、约束及化简依据。已有正文足以识别时直接使用，不要求另填全量登记。缺项仅限制相应判断：仍可做结构规划、讲解建议或表达修订，未定义的类型、行动和约束不代为补造。

## “文献”有哪些不同用途

- **研究来源**：本章真正使用的论文、报告、数据、作者研究结果。需要转述其模型或重要结论时，应提供相关正文及必要附录。
- **写法参照**：中文参考专著、样章或出版社范例，用来说明期望的组织和表达。属于可选材料，除非任务明确要求对照某个范例。
- **格式依据**：出版社要求、引证规范、作者已采用的格式。已有要求请提供；尚未选定出版社时可以先按中文学术专著体裁推进，并列出需后续确定的格式项。

维护者用来提炼本 skill 规则的参考专著，不需要使用者每次重新上传。参考专著也不能替代本章使用的研究原文。

## 怎样选用具体格式

通用符号、名称与图表要求见[排印指南](../skills/chinese-research-monograph/references/typography-and-names.md)。本仓库另有作者提供的[16开格式配置](../skills/chinese-research-monograph/references/format-profile-16k.md)：包含简介300—400字、三级目录、14×22厘米版心、标题层级、图表与扫描参数。它不是所有专著的默认格式；出版社身份/版本及损坏条款仍须按实际资料确认。

任务可写“沿用已约定的16开规范”或“选用 cn-monograph-16k-author-supplied，按本次Word交付范围执行，损坏条款保持待核”。不必上传所有研究文献才能做格式设置，也不能为了排版重写正文或改动模型。另有出版社文件时直接使用该文件，记录冲突即可。

这两份指南是v0.4.0发布后的仓库补充，旧tag及Release附件不含它们。取得补充时使用包含本次改动的确定commit及skills/chinese-research-monograph路径，记录commit；metadata.version仍为0.4.0，本次不创建新Release、不覆盖旧附件。

## 文件怎样准备

|材料|推荐提供方式|需要注意什么|
|---|---|---|
|书稿|DOCX、Markdown，或直接提供相应正文；PDF可用于阅读与版面检查|说明哪份是当前底本，以及只读审核还是允许修订|
|论文与专著|可读PDF、EPUB、正文文件或清晰扫描；也可先提供题名、DOI和来源链接|正文、公式、图表和附录应清楚；扫描可能需要OCR与原页核看，实际能力取决于环境|
|参考文献库|BibTeX、RIS或完整书目清单|有助于匹配身份和编排引证，但书目文件不是全文，不证明引文内容正确|
|数据与计算|实际数据、参数表及需要复现的脚本和运行说明|说明单位、样本/情景、目标结果，以及哪些输入与版本对应|
|中文规范|出版社文件、格式示例、作者已有术语表|说明强制要求与作者偏好；未确定事项不猜作出版社规定|

如果材料较多，可以按章节分组，附一份简短清单：资料名称、文件、用途、版本或日期。清单可直接写在消息里，不必制作复杂表格。使用者提供的文件应在当前任务中可读；GitHub 仓库只需要托管通用规则、指南和自拟示例，不需要把研究文献或书稿上传到仓库。

## 最小任务说明

把已有信息用一段话说明即可，不强制填写模板：

> 这次做什么，处理哪章或哪段，写给谁看；哪份是底本，哪些材料是研究依据，必须保留什么；允许改到什么程度；需要什么交付，完成后在哪里停止。

例如：

> 使用 $chinese-research-monograph，只审核附件中的第4章，目标读者是经管研究生。章稿为当前底本，另外两篇论文用于核对模型设定。本次给审核意见，不修改书稿。重点检查信息结构、采购时序及结论条件，完成后停止。

这份说明不构成全文上传、固定字数或固定文献数量的要求。已知信息直接继承，不要求用户重复回答。

## 可以直接使用的任务示例

### 从想法开始规划

```text
使用 $chinese-research-monograph，规划一本面向经管研究生的中文专著，
主题是农业供应链管理。先根据我的研究方向和现有成果拟定全书主线与目录，
说明每章解决什么问题及需要补充哪些研究材料。本次不写整章。
```

### 根据论文和成果写章节

```text
使用 $chinese-research-monograph，根据附件中的章节说明、两篇论文正文及附录，
完成第3章中文正文。按中文研究型专著组织，讲清关键设定、代表性推导和机制。
保留原结果的条件，说明本书新增的简化或综合；来源核查说明独立成文。
交付连续可读的Markdown，完成后停止。
```

### 只有正文，先做润色

```text
使用 $chinese-research-monograph，润色下面这一节的中文表达。
保留公式、事实、结论强度及术语，只调整段落和句子。
本次材料只有正文，请按表达修订的范围交付。
```

### 审阅完成的专著

```text
使用 $chinese-research-monograph，系统审阅附件中的全书，面向经管研究生。
按中文学术专著规范检查研究主线、章节递进、解释深度、内部一致性和中文表达。
先形成总体判断，再给有定位的逐章意见，并记录实际阅读范围。
外部引证核验和数学复算分别说明。本次只审核，不改原稿。
```

### 深入核查一个模型

```text
使用 $chinese-research-monograph，核查第4章4.2节及对应来源论文的模型和证明。
重点核对主体、信息、行动时序、目标和结论条件。
核查提供的参数实例；若执行复算，请给出实际方法、输入和结果。
给有定位的意见，不把未执行的计算记为通过。
```

### 缺少文献，需要补查

```text
使用 $chinese-research-monograph，先处理我提供的本章材料。
对支撑本章核心机制仍缺少的来源，围绕已确定的问题补充调研。
优先核读最相关工作；无法获取的核心原文列成书目与所需范围清单，
继续完成不依赖缺失材料的部分。
```

### 按指定意见复审

```text
使用 $chinese-research-monograph，只复审第4章修订稿及意见清单中的指定项目，
核查必要关联内容。分别报告已解决、部分解决、未解决和未核事项。
本次不启动其他章节重写。
```

## 材料不足时怎样继续

收到材料后，skill 应先确认实际可读的文件、任务范围、底本和材料用途。通常只需简短说明；长稿或来源较多时再做清单。

能据现有材料完成的工作继续执行。例如只有书稿时，可以审阅结构、表达及部分内部一致性；只有主题时，可以讨论目录和研究路线。某项工作需要缺失来源、数据或不可读公式时，说明受影响的具体论断及最小补充要求，不把整本任务一概停下。

报告中的“读过书稿”“核过原文”“复算过结果”“看过版面”分别指实际完成的工作。读取附件或通过文件检查，不等于全部引证已核实、全部模型已验证或已经出版定稿。

## 怎样安排较大的项目

可按实际需要选择“全书规划—代表性章节试写—章节写作—跨章统稿—系统审核—指定修订复审”的阶段，也可以直接进入已明确的局部任务。各阶段确认底本、输出和停止位置；不要求重新完成前面已经确认的工作。

每阶段的反馈用于修正结构和规范，最终稿的作者审定及出版社决定仍按实际状态记录。

## 含数学文件的交付

含数学文件回读实际落盘表达，在实际提供的显示路径检查关键公式；可按需使用[只读扫描与安全写入](../skills/chinese-research-monograph/references/math-text-check.md)。扫描提示须按上下文处理，无告警不证明数学正确。纯聊天、目录规划或不含数学的局部文字不强制运行检查；只交Markdown不强制新建Word。Word仍检查最终文件页面，未测显示环境如实登记。
